# Project Development Guidelines

## General
- Understand the existing project architecture before modifying code.
- Do not rewrite existing modules unnecessarily.
- Keep the code modular and maintainable.
- Explain major architectural decisions.

## Git Workflow
- Never delete or overwrite existing work without approval.
- Never push directly to GitHub without my approval.
- Never commit API keys, passwords, tokens or .env files.
- After implementing a feature, summarize all modified files.
- Run relevant tests before suggesting a commit.
- Suggest a meaningful Git commit message after each completed feature.
- Do not modify unrelated files.

## Development Process
1. Understand the requirements.
2. Inspect the existing codebase.
3. Propose an implementation plan.
4. Implement the changes.
5. Run tests.
6. Explain the changes.
7. Suggest a commit message.
